## Screen Translation Matrix

Source rows are defined in `scripts/screen_translation_eval_cases.tsv`; keep this table aligned with that TSV when adding or removing manual cases.

Result format:

- `Pass: evidence build/rc-device-evidence/<timestamp> checklist=layout_ok,language_ok,...`
- `Fail: numeric_corruption`
- `Fail: language_leakage`
- `Fail: layout_grouping`
- `Fail: paging_duration`
- `Fail: ocr_api`
- `Blocked: missing BYOK key`
- `Blocked: cannot reproduce screen`

Pass evidence must be the unique timestamped directory produced by `./scripts/rc_device_evidence.sh --gate screen_translation --case-id <case_id> --include-screenshot` under `build/rc-device-evidence/`, and it must contain `README.md`, `health.json`, `latest-request.json`, `hotkey-voice-overlay.json`, `screenshot.png`, and a `metadata.json` whose `gate` is `screen_translation` and whose `case_id` matches the row. Capture screenshots only when no API key, personal data, ROM path, or long copyrighted text is visible. Pass rows must also keep the generated `checklist=` tokens for that case so the report can verify the tester checked layout, language, numbers, or paging.

Use `scripts/screen_translation_matrix_update.py` to update rows safely instead of editing the table by hand, for example:

```bash
# Capture evidence with:
# ./scripts/rc_device_evidence.sh --gate screen_translation --case-id ff6_dialogue --include-screenshot
#
# Replace <timestamp> with the real evidence directory captured for this case before using --apply.
python3 scripts/screen_translation_matrix_update.py \
  --cases scripts/screen_translation_eval_cases.tsv \
  --case-id ff6_dialogue \
  --result "Pass: evidence build/rc-device-evidence/<timestamp> checklist=layout_ok,language_ok,no_english_source" \
  --output /tmp/retrosprite-screen-matrix-ff6_dialogue.md

# After reviewing the preview, rerun the same command with --apply.
```

`scripts/screen_translation_eval_report.py --strict` only passes when every row is `Pass` and every pass row points to a unique existing `rc_device_evidence.sh` output directory containing `README.md`, `health.json`, `latest-request.json`, `hotkey-voice-overlay.json`, `screenshot.png`, and matching `metadata.json`, plus the required `checklist=` tokens. Failed or blocked rows must include a concise category so the next M18 backlog pass can group them.

## Evidence To Capture

Run this after a manual hotkey voice or screen translation attempt:

```bash
./scripts/rc_device_evidence.sh
```

It requires one online adb device and writes a timestamped folder under `build/rc-device-evidence/` with:

- `/debug/hotkey-voice-overlay`
- `/debug/latest-request`
- `/health`
- `metadata.json` with the manual gate and case id
- `screenshot.png` when captured with `--include-screenshot`
- adb device, package, AppOps, and window state snapshots
- API provider/model shown in Settings or Diagnostics for live screen translation
- Screenshot or photo only when it contains no ROM path, personal data, API key, or long copyrighted text
